# Руководство контрибьютора (CONTRIBUTING)

Этот документ содержит подробную информацию об архитектуре проекта, правилах написания кода и инструкциях для локальной разработки.

## Архитектура проекта

Проект организован в виде монорепозитория, что позволяет жестко отделить бизнес-логику от UI и переиспользовать код.

### 1. Ядро и контракты (`re_ucm_core`)
Pure-Dart пакет, не зависящий от Flutter. Содержит:
- Контракты порталов (`Portal`, `PortalService`).
- Интеграцию с библиотекой `dart_book` (метаданные, структура книги).
- Схемы UI-настроек, которые рендерятся динамически (`PortalSettingItem`).
- Глобальные модели прогресса и логгер.

### 2. Бизнес-логика (`re_ucm_lib`)
Pure-Dart пакет, отвечающий за "движок" приложения:
- **Сборка книг:** `BookExporter` выполняет подготовку и генерацию файлов (`fb2`, `fb2.zip`, `epub`) в отдельном **Isolate**, чтобы не блокировать UI-поток приложения.
- **Хранилище:** Используется `Sembast IO` для локального NoSQL хранения настроек сессий (`SettingsService`) и истории скачиваний (`RecentBooksService`).
- **State Management:** Реактивность на уровне бизнес-логики обеспечивается с помощью `MobX`.

### 3. Модули порталов (директория `portals/`)
Каждый поддерживаемый ресурс выносится в отдельный пакет внутри папки `portals/` (`portals/re_ucm_author_today`, `portals/re_ucm_ficbook`). Модуль реализует логику авторизации (через токен или куки встроенного браузера), обхода защит (например, AES-расшифровка текста) и парсинга контента согласно общим интерфейсам из `core`.

### 4. Вспомогательные плагины (директория `plugins/`)
Локальные платформенные адаптеры и стабы (`plugins/zikzak_share_handler_windows`, `plugins/zikzak_share_handler_linux`) для обеспечения сборки под десктопные системы.

### 5. Клиентское приложение (`re_ucm_app`)
Основное Flutter-приложение для Android, Windows, Linux, macOS и iOS. 
Архитектура приложения построена по подходу **Feature-first**:
- Код разделен по изолированным фичам в директории `lib/features/` (`home`, `book`, `browser`, `settings` и т.д.).
- **Внедрение зависимостей (DI):** Глобальные сервисы бизнес-логики прокидываются в дерево виджетов через класс `AppDependencies` (см. `lib/core/di.dart`).
- **State Management (UI):** Состояние экранов управляется MobX-сторами, а виджеты реагируют на изменения, будучи обернутыми в `Observer`.

## Локальная разработка и сборка

Для работы с проектом вам понадобятся установленный Flutter и Dart SDK.

### Шаг 1. Получение зависимостей
```bash
flutter pub get
```
Эта команда подтянет зависимости для всех пакетов в воркспейсе.

### Шаг 2. Кодогенерация
В проекте активно используется кодогенерация (MobX, Freezed, Retrofit). После изменения моделей или сторов необходимо перегенерировать служебные файлы (`.g.dart`, `.cg.dart`, `.freezed.dart`):
```bash
dart run build_runner build -d --workspace
```
> **Совет:** Во время активной разработки можно использовать `dart run build_runner watch -d --workspace` для автоматической перегенерации файлов "на лету" при сохранении.

### Шаг 3. Запуск приложения
```bash
cd re_ucm_app
flutter run
```

## Добавление нового ресурса (Портала)

Если вы хотите добавить поддержку нового сайта, вам нужно создать новый пакет внутри директории `portals/` (по аналогии с `portals/re_ucm_author_today`).

### План реализации:
1. **Создание пакета:** Создайте директорию `portals/re_ucm_yourportal` с файлом `pubspec.yaml` (не забудьте указать `resolution: workspace`).
2. **Конфигурация:** Добавьте путь `portals/re_ucm_yourportal` в массив `workspace:` в корневом `pubspec.yaml` и в зависимости `re_ucm_app/pubspec.yaml`.
3. **Настройки:** Реализуйте структуру настроек модуля, унаследовав `PortalSettings`.
4. **Сервис:** Создайте класс, реализующий `PortalService<TSettings>`. Здесь будет находиться логика HTTP-запросов, парсинга HTML/JSON ресурса и конвертации структуры в формат библиотеки `dart_book`.
5. **Портал:** Создайте класс, реализующий `Portal<TSettings>`, где укажите базовую информацию о сайте (URL, название, логотип) и свяжите его с вашим сервисом настроек.
6. **Регистрация:** В основном приложении (`re_ucm_app/lib/core/di.dart`) добавьте инстанс вашего портала в фабрику инициализации:
   ```dart
   PortalFactory.registerAll([
     AuthorToday(),
     YourNewPortal(), // <-- Добавьте ваш портал сюда
   ]);
   ```
